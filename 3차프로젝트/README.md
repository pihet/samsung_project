# 3차 프로젝트: 쿠션(CUSHION)

> **정식 주제명:** 딥러닝 기반 실시간 고객 음성 감정 완화 및 상담원 보호 데이터 플랫폼 구축
>
> **부제:** 고객의 화는 낮추고 상담원의 하루는 지키는 실시간 음성 완충 AI
>
> 상태 (2026-11-18): 주제명 확정. **첫 주 검증 시험(보정하면 정말 차분하게 들리는가) 전**이라 시험 결과에 따라 범위가 바뀔 수 있습니다.

---

## 1. 한 줄 요약

고객이 전화로 소리를 질러도 상담원 귀에는 누그러진 목소리로 들리게 바꾸고, 관리자는 대시보드로 상담원별 폭언 노출을 확인해 휴식과 보호 조치를 내립니다.

## 2. 왜 필요한가

| 근거 | 내용 |
|---|---|
| AI 도입이 문제를 키움 | 한국노총 중앙연구원 조사(2026년 1월 발표): AI 상담 도입 후 일평균 민원 17.9% 증가, 응답자 61%가 "노동조건 악화". AI 상담에 짜증 난 고객이 결국 사람 상담원에게 넘어와 화를 냄 |
| 법적 의무 | 산업안전보건법 제41조: 사업주는 고객 폭언으로부터 고객응대 근로자를 보호해야 함(업무 일시 중단·전환, 휴게시간 연장, 치료·상담 지원). **대시보드가 이 조치의 기록**이 될 수 있음 |
| 실제 피해 사례 | 2026년 6월, 1년간 콜센터에 약 1만 번 전화해 욕설·성희롱을 한 40대 남성 검거 보도 |
| 해외 상용화 | 일본 소프트뱅크가 화난 목소리를 누그러뜨리는 서비스를 상용화. **국내 도입 사례는 검색에서 찾지 못함** → 한국어 버전이 차별점 |

발표용 메시지: **"AI가 만든 화, AI가 받아낸다."**

인용 주의: "콜센터 노동자 77.9% 폭언 경험" 수치는 원자료를 확인하기 전에는 쓰지 않기.

## 3. 핵심 기능

1. **분노 판별 (딥러닝):** 짧은 구간마다 고객 음성이 얼마나 화났는지 점수로 매김
2. **실시간 보정:** 점수만큼 보정 세기를 조절
   - 단순 보정(기본): 고함 크기 누르기, 거친 고음(2~5kHz) 깎기. 지연 수십 ms, 개인 PC로 가능
   - 딥러닝 감정 변환(확장 목표): 화난 목소리를 차분한 목소리로 변환. 연구 수준이라 실패해도 프로젝트가 무너지지 않게 확장으로만 둠
3. **욕설 구간 표시:** 단어를 끝까지 들어야 욕인지 알 수 있어 실시간 삭제 대신 화면 표시와 기록
4. **관리자 대시보드:** 상담원별 폭언 노출 시간, 휴식 권고, 보호 조치 이력, 모델 버전별 성능

## 4. 지연 시간 기준

- ITU G.114 권고: 한쪽 방향 지연 150ms 이하 권장, 400ms까지 허용 수준
- 목표: 보정 경로 0.3초 이내. 분노 점수는 1초쯤 늦어도 보정이 끊기지 않는 구조
- 시연은 실제 휴대폰 통화망이 아니라 **PC끼리의 인터넷 통화**로 진행(안정성)

## 5. 데이터

- **학습:** AI Hub 한국어 감정 음성 데이터(논문 기준 두 종류 확인, 세부 조건 미확인)
  - 감정 분류를 위한 대화 음성: 분노·행복·보통·슬픔 4가지
  - 감성 발화 데이터: 성우 50명 이상, 7가지 감정
  - **승인에 며칠 걸릴 수 있어 가장 먼저 신청**
- **모델:** wav2vec 2.0 / HuBERT 같은 사전학습 음성 모델에 감정 판별만 덧붙여 학습
- **전화 음질 대응:** 공개 데이터를 전화 음질로 변환해 학습(데이터 증강 효과도 있음)
- **실전 시험:** 팀원들이 실제 전화로 화난 연기를 한 녹음 수백 개

## 6. 데이터 엔지니어링 (발표 반응 6 : 데이터 엔지니어링 4)

실시간 음성 보정은 상담원 PC 옆에서 돌아가고, Databricks는 결과를 쌓고 분석하는 곳입니다. 그래서 아래 세 가지를 **실제 데이터 엔지니어링 과제**로 둡니다.

1. **여러 음성 데이터셋 통합:** 데이터셋마다 다른 감정 분류(4종 vs 7종), 파일 형식, 음질, 화자 정보를 공통 기준으로 맞추고 품질 검사와 버전 관리를 붙인 음성 데이터 레이크하우스
2. **스트리밍 부하 시험:** 가상 통화 수백 건을 동시에 흘려 "동시 N통화에서 대시보드 반영 지연 X초 이내" 같은 성능 목표를 수치로 검증
3. **오탐 신고 → 재학습 순환:** 상담원이 "화난 게 아니었다"고 표시한 구간이 정제되어 다음 학습 데이터로 자동 반영, 모델 버전별 성능 추적

사생활: 원본 음성은 저장하지 않고 점수와 메타데이터만 남기는 보관 정책.

### Databricks Free Edition 제약 (공식 문서 기준)

- 서버리스만 가능, 일일 사용량 초과 시 그날 연산 중단
- **외부 인터넷 접근이 신뢰된 도메인으로 제한** → 데이터 수집은 로컬에서 하고 업로드
- GPU 모델 서빙 불가 → 실시간 추론은 Databricks 밖에서
- 미확인: 팀원 초대 가능 여부, 사용 가능한 Foundation Model API 목록

## 9. 예상 질문

- **"음성 감정 인식은 흔하지 않나?"** → 신선함은 "실시간으로 목소리를 바꿔 상담원을 지킨다"는 비틀기에서 나옴. 그래서 보정 품질이 핵심
- **"우리 회사와 무슨 상관?"** → 감정노동과 고객응대 근로자 보호 의무는 모든 회사에 해당. 카메라는 쓰지 않음
- **"이미 소프트뱅크가 하지 않나?"** → 맞음. 한국어 버전이 없고, 우리는 데이터 플랫폼과 보호 조치 기록까지 다룸

## 10. 첫 주 검증 시험

`soften_test.py`로 화난 연기 녹음(10초 안팎 3~4개, wav)을 두 단계로 보정해 들어봅니다.

```bash
cd 3차프로젝트
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python soften_test.py 녹음.wav
```

녹음 파일(wav, m4a)은 개인 음성이라 `.gitignore`로 커밋에서 제외합니다.

- `*_soft1.wav`: 크기 압축 + 거친 고음 깎기 (실시간 처리가 쉬운 방식)
- `*_soft2.wav`: soft1 + 억양 폭 절반 + 음높이 8% 낮추기
- 들을 때: 보정본이 작게 들려 "조용해졌다"와 "차분해졌다"가 헷갈리므로 볼륨을 맞추고 비교. 팀원 2~3명에게 순서를 섞어 들려주기
- **통과하면 4주 계획으로, 별로면 주제 재검토**
