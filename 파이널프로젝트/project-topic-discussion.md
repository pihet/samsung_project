# 최종 프로젝트 주제 선정 논의 정리

> 다른 AI에게 맥락을 전달하기 위한 문서입니다. 2026-11-17 기준, Claude와 나눈 대화를 정리했습니다.
> 아직 주제는 **확정되지 않았습니다.** 이 문서의 목적은 "지금까지 무엇이 왜 탈락했는지"와 "사용자가 원하는 조건"을 넘겨서, 같은 제안을 반복하지 않게 하는 것입니다.

---

## 1. 상황

- 사용자는 **삼성중공업 스마트 조선소 AI 전문가 과정** 교육생입니다. 딥러닝까지 배웠습니다.
- **최종 프로젝트 기간은 약 4주**, 팀원은 **5~6명**입니다.
- 결과는 **삼성중공업 그룹장들 앞에서 발표**합니다. 그룹장들은 여러 교육생 프로젝트를 이미 본 사람들입니다.
- 사용자는 **데이터 엔지니어 분야**를 공부하고 싶어 합니다. 다른 팀원들은 데이터 엔지니어링을 잘 모릅니다.
- **팀원들은 사용자가 정한 주제를 따르기로 했습니다.** 그래서 사용자 본인이 마음에 드는 주제여야 합니다.
- 팀원들이 AI 코딩 도구를 쓰므로 개발 속도가 빠릅니다. **범위가 작으면 "한 달 동안 널널하다"고 느낍니다.**

## 2. 확정된 조건 (사용자가 직접 말한 것)

### 반드시 포함
- **딥러닝 프로젝트**여야 합니다.
- **Databricks로 데이터를 관리**해야 합니다.
- **최종 결과물은 대시보드**여야 합니다.
- **카메라를 사용**하고 싶어 합니다. 형태(착용형, 고정형, 여러 대)는 상관없습니다.
  - 최근에는 "그냥 주제를 계속 말해 달라, 하나 얻어걸리면 된다"고 해서, 카메라가 없는 후보도 받고 있습니다.

### 선호
- **현재 이슈**를 다루는 걸 굉장히 좋아합니다. 예: 스마트안경, 초소형 카메라, 수능 AI 부정행위 논란
- 그룹장들이 **"재밌다, 직접 해보고 싶다"**는 반응을 보이길 원합니다. 단, 대기업 발표 자리에 맞는 품격이 있어야 합니다.
- 실무에 연결되거나 기술을 써먹을 수 있다는 느낌이 있어야 합니다.
- **흔한 주제에 "나만의 기술"을 더해 새롭게 만드는 것**도 괜찮다고 했습니다. 다만 그 기술이 무엇인지 모르겠다고 했습니다.
- 데이터 엔지니어링으로 경험하고 싶은 것: **여러 소스 통합, 실시간 스트리밍, 대용량 배치 처리**
- 대시보드를 볼 사람: **관리자·운영자**
- 대시보드에서 보고 싶은 지표: 흐름·혼잡, 이상·위험 상황, 변화·추세, 사용·낭비 (전부 선택)
- 카메라가 볼 대상: "사람이 나을 것 같은데, 아니면 물건?" (확정 안 됨)
- 회사 실무에서는 **온톨로지와 RAG** 관련 작업을 하고 있는 것 같다고 언급했습니다.

### 금지 / 기피
- **캐글 데이터는 쓰지 않습니다.**
- **조선 도메인 관련 주제는 피하고 싶어 합니다.** 그룹장(조선 현업 전문가)의 도메인 질문을 방어하기 싫기 때문입니다. 조선은 데이터가 없어서 "속 빈 강정"이라고도 했습니다.
- **흔한 주제는 싫어합니다.** 이게 가장 자주 나온 탈락 사유입니다. "여러 프로젝트를 본 사람들 앞에서 많이 나온 주제가 나오면 재미없다."
- **작업 숙련, 숙련자 비교, 현장 작업 관련 주제는 절대 금지**라고 강하게 말했습니다. 숙련자를 구할 수 없어 불가능하다고 봅니다.
- **게임 형식은 금지**입니다. 대기업 발표 자리에 맞지 않습니다.
- **너무 공공적인 주제(공공기관이 할 법한 것)는 별로**라고 했습니다.
- **회사가 이미 하고 있을 것 같은 주제는 별로**라고 했습니다.
- **과정 운영자나 현업 멘토에게 물어보는 건 어렵다**고 했습니다.

### 제약
- **개인 장비 성능이 좋지 않습니다.** 무거운 딥러닝 학습은 어렵습니다.
- 스마트안경 등 장비 **예산이 제한적**입니다.
- 처음에는 Databricks 관리를 위해 "데이터가 꽤 많아야 한다"고 했습니다.

## 3. 탈락한 주제와 이유

같은 주제나 비슷한 결의 주제를 다시 제안하지 않도록 정리합니다.

| 주제 | 탈락 이유 |
|---|---|
| AIS 선박 항적 이상 탐지·ETA 예측 | 조선 관련이라 도메인 질문 방어가 싫음 |
| 위키백과 실시간 악성 편집 탐지 | 별로 |
| 기상 레이더 강수 나우캐스팅 | 별로 |
| e스포츠 승부 예측, 특허 유사도 검색, 공시·뉴스 주가 급변 탐지, 지하철 지연 예측, 음악 장르 분류·추천 | 전부 별로 (흔함, 재미없음, 임팩트 약함) |
| 우주쓰레기 충돌 경보, 실시간 지진 감지, 태양 플레어 예보 | 신선하지만 직관적으로 와닿지 않음 |
| 서울 핫플 인파 밀집 예측, 응급실 포화 예측, 깡통전세 탐지 | 흔함 |
| 고속도로 CCTV로 도로 결빙·안개 판정 | 별로 |
| 제조 공정(용접) 데이터 플랫폼 (공개 데이터를 사내 데이터 대역으로 사용) | 와닿지 않음 |
| 작업자 시점 현장 안전 어시스턴트 (카메라 + 온톨로지 + RAG) | 이후 방향이 바뀜 |
| 저비용 AI 촬영·통신 기기 탐지 (전파 + 영상) | 부정적으로만 본다는 피드백 |
| 숨겨진 카메라 탐지 (렌즈 반사 + 전파) | 부정적 활용이 아니라 긍정적 활용을 원함 |
| 숙련자 시점 작업 노하우 전수, 다국어 작업 가이드 | 이미 하고 있을 것 같음 (실제로 삼성중공업이 AI 통역 '스콘챗' 도입) |
| 산업 문서를 AI용 데이터로 변환하는 파이프라인 (+ 온톨로지 확장판) | 처음엔 한 달에 비해 작다, 확장하니 리스크가 크다, 흥미가 안 생김 |
| AI 숙련도 챌린지 (손동작으로 숙련자와 비교) | 숙련자 기준을 만들 수 없음, 작업 숙련 주제 자체를 거부 |
| 발표 중 스스로 배우는 비전 AI ("AI를 이겨라") | 대기업 발표에서 게임은 부적절 |
| 카메라 영상의 실시간 개인정보·기밀 자동 가림 | "민감한 글자를 어떻게 정하나" 질문 후, 결국 OCR·CLIP 조합이라는 인식 |
| 큰 모델 → 초소형 보드용 작은 모델 지식 증류 | 애매함 |
| 교육장 공간 운영 대시보드, 공개 실시간 카메라 인파 분석 | 별로 |
| 사내식당 잔반 분석, 출입 꼬리물기, 에너지 낭비, 분리배출, 엘리베이터 대기, 주차, 비품 재고, 흡연 감지 | 너무 흔함 |
| 카메라로 보이지 않는 물리량 측정: 하천 유속, 미세먼지 추정 | 너무 공공적 |
| 카메라로 보이지 않는 물리량 측정: 기계 진동 | "괜찮은 느낌"이라고 했던 유일한 주제. 이후 "센서가 이미 있지 않나", "저가로 됐으면 다들 썼겠지", "AI한테 맡기면 되지 않나" 질문이 나왔고 최종적으로 다른 것과 함께 "다 별로" |
| 구조물 미세 변형, 두드려서 속 결함 찾기, 조명 각도로 숨은 흠집, 가스·열 누출 시각화, 비접촉 심박, 영상 속 전력망 신호로 위변조 검증 | 다 별로 |

### 탈락 패턴 (중요)
- 조건들이 서로 충돌합니다. **직관적이고 데이터가 많으면 흔하고, 신선하면 와닿지 않고, 실무와 가까우면 이미 회사가 하고 있거나 도메인 질문이 걱정됩니다.**
- 사용자가 **"괜찮은 느낌"이라고 반응한 유일한 결**은 **"평범한 카메라로 눈에 안 보이는 것을 측정한다"(기계 진동)**였습니다. 그 뒤 같은 결의 후보를 여러 개 냈지만 모두 탈락했습니다.
- 사용자는 **카메라 프로젝트가 결국 OCR이나 CLIP 같은 사전학습 모델 조합**이라는 점에 실망을 표했습니다.

## 4. 마지막으로 제시한 후보 (사용자 반응 대기 중)

사용자가 "주제를 계속 말해 달라, 하나 얻어걸리면 된다"고 해서 한 줄씩 던진 목록입니다. 이 목록에 대한 반응은 아직 받지 못했습니다.

**카메라 + 회사·보안**
1. 화상회의 딥페이크 탐지 (CEO 사칭 딥페이크 화상회의 송금 사기 사례가 해외에 실제로 있음)
2. 모니터 화면 촬영 감지 (정보 유출 방지)
3. AI 생성 이미지·영상 판별기
4. 일반 웹캠 시선 추적으로 문서 가독성 측정

**카메라 + 3D·디지털 트윈**
5. 폰 영상 한 편으로 공간 디지털 트윈 만들기 (Gaussian Splatting)
6. 손 스케치를 3D 모델로
7. 카메라로 상자 부피 자동 측정

**위성·외부 데이터 + 경쟁 정보**
8. 무료 위성 영상으로 전 세계 경쟁 조선소 도크의 선박 수를 세서 경쟁사 동향 대시보드 만들기 (공정 지식이 아니라 경쟁 정보라서 도메인 질문 부담이 적음)
9. 뉴스·공시로 경쟁사 수주 자동 추적
10. 위성으로 전 세계 항만 혼잡 추적

**AI 도입 자체를 다루는 주제**
11. 사내 AI 챗봇 답변 품질(환각) 감시 시스템
12. 부서별 AI 사용 비용·효과 대시보드
13. AI가 생성한 코드의 보안 취약점 추적

**완전히 다른 결**
14. 폰 마이크로 기계 소리 이상 진단
15. 사진 한 장으로 재질 판별
16. 회의 녹음 발언 분석기

Claude는 그룹장 반응이 클 것 같은 후보로 **8번(위성 경쟁사 추적)**과 **1번(딥페이크 화상회의 탐지)**을 꼽았습니다.

## 5. 대화 중 확인한 사실 (웹 검색 기준, 2026-11)

### Databricks Free Edition 제약 (공식 문서)
- 서버리스 연산만 가능합니다. 공정 사용 한도를 넘으면 그날 연산이 중단됩니다.
- **외부 인터넷 접근이 신뢰된 도메인으로 제한됩니다.** 공공 API를 Databricks 안에서 직접 호출하지 못할 수 있으므로, 로컬에서 수집해 업로드하는 구조가 필요할 수 있습니다.
- GPU 모델 서빙이 불가능하고, 프로비저닝 처리량도 없습니다.
- 벡터 검색(AI Search)은 엔드포인트 1개, 검색 유닛 1개까지입니다.
- SQL 웨어하우스는 1개(2X-Small)입니다. 작업은 동시 5개, Lakeflow 파이프라인은 종류별 1개까지입니다.
- Apps는 3개까지이고, 24시간 후 자동 정지됩니다.
- 계정당 워크스페이스 1개입니다. 비상업용만 허용됩니다.
- **확인 못 한 것:** 팀원 초대 가능 여부, Free Edition에서 쓸 수 있는 Foundation Model API 모델 목록
- 출처: https://docs.databricks.com/aws/en/getting-started/free-edition-limitations

### 공공 데이터
- KOSHA GUIDE 조회 API(공공데이터포털)가 있습니다. 2026년 1월 정비 후 1,039건으로 운영됩니다.
- 안전보건공단 물질안전보건자료(MSDS) 조회 API가 있습니다. 무료, 이용 제한 없음, XML, 16개 항목(보호구 항목 포함)입니다.
- 사망사고 고위험요인(SIF) 아카이브 API가 2026년 8월에 등록됐습니다.
- Ultralytics Construction-PPE 데이터셋은 1,416장, 11개 클래스입니다.
- AI Hub의 안전장비·용접 데이터셋은 확인하지 못했습니다.

### 현재 이슈
- **수능(2027학년도, 2026-11-19 시행) 직전 AI 스마트안경·초소형 카메라 부정행위 우려가 커졌습니다.** 올해 세무사 시험 수석 합격자가 초소형 카메라와 생성형 AI로 부정행위를 했다고 인정해 경찰 수사로 이어졌습니다. 교육부는 수능 연기는 없다고 밝혔고, 시험장마다 판별 전담 인력을 1명씩 둡니다. 초소형 카메라는 외형 식별이 어렵고, 열화상·전파 차단은 기술적·제도적 한계로 즉시 도입이 어렵다는 입장입니다. 초소형 카메라 품절 기사도 나왔습니다.
- **메타 Wearables Device Access Toolkit 1.0이 정식 출시**됐습니다(Meta Connect 2026). 카메라 스트리밍과 사진 촬영을 지원하지만, 전체 기능은 AI 안경 출시 국가에서만 쓸 수 있습니다.
- **삼성중공업은 2026년 외국인 근로자 안전교육에 AI 실시간 통역 '스콘챗'을 시범 도입**했습니다. 2026년 3월에는 작업중지권 선포식을 열었습니다. 조선업 근로자의 약 20%가 외국인입니다(2024년, 안전보건공단 관계자).

### 카메라 하드웨어 관련
- 사용자가 본 알리 상품은 "4K 미니 매크로 WiFi 카메라, 휴대폰 원격 보기"(약 7만 원)입니다. 전용 앱 방식일 가능성이 높아 **AI 직접 연동은 불확실**합니다. RTSP나 ONVIF 지원 여부를 확인해야 합니다.
- AI 연동이 쉬운 카메라: XIAO ESP32S3 Sense, ESP32-CAM, USB UVC 카메라, RTSP 지원 IP 카메라
- 전용 앱 카메라를 우회하는 방법: scrcpy로 폰 화면을 PC에 미러링해 캡처
- 알리 배송은 1~3주 걸릴 수 있습니다.
